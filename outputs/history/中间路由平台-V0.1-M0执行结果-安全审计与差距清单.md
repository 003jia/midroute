## 4. 安全审计

### 4.1 CLIProxyAPI

| 审计项 | 现状 | 评级 |
|---|---|---|
| 凭据存储 | OAuth Token / API Key 以明文 JSON 存于 `~/.cli-proxy-api/` | 高 |
| 网关访问鉴权 | `api-keys` 列表鉴权；管理 API 使用独立 `secret-key`（启动时哈希） | 良 |
| 日志脱敏 | 内置 `HideAPIKey` / `MaskSensitiveQuery`（保留 Bearer 前缀、仅掩蔽凭据段） | 良 |
| 默认监听地址 | `host` 默认 `""` 绑定全部网卡（IPv4+IPv6） | 高 |
| 上游 Base URL 协议 | 未发现强制 HTTPS / SSRF 拦截（云元数据、本机敏感端口）校验 | 中 |
| 依赖供应链 | go.mod 依赖锁定，无运行时插件默认加载 | 中 |

### 4.2 CPA-Manager-Plus

| 审计项 | 现状 | 评级 |
|---|---|---|
| 管理密钥存储 | CPA Management Key 使用 AES-GCM（`enc:v1:` 信封）+ `data.key` 加密入库 | 良 |
| 管理台鉴权 | `cmp_admin_...` admin key 鉴权 | 良 |
| 数据面 | SQLite 仅存用量元数据，不存凭据明文；`fail_body`/`raw_json` 仅本地保留、导出脱敏 | 良 |
| 默认监听地址 | `HTTP_ADDR` 默认 `0.0.0.0:18317` | 高 |
| Prompt 持久化 | 默认不持久化 Prompt/回答，仅元数据 | 良 |

## 5. 差距清单（对计划 V0.1）

### 5.1 上游已覆盖、可直接复用

- OAuth / API Key Provider 管理（Codex、Claude Code、Gemini、OpenAI 等登录）。
- OpenAI-compatible 网关、多账号轮换、模型映射、故障切换与 usage 事件。
- 请求级 Token / 缓存 Token / reasoning Token / 延迟与错误统计。
- SQLite 用量持久化、费用估算、配额窗口与账号健康页面。
- CPA Management Key 的 AES-GCM + data.key 加密。

### 5.2 仍需自行实现或改造（计划 §18「仍需自行实现或改造」）

| # | 差距项 | 现状 | 目标 | 建议落点 |
|---|---|---|---|---|
| G1 | 模型拥挤度/健康评分 | 只有延迟与失败分析 | 带置信度、样本数、TTFT P50/P95、429/5xx/超时率、故障分类（account_limited / provider_degraded / model_busy_inferred / network_issue） | M2，health 模块 |
| G2 | 官方组织 Usage/Cost API 与对账 | 未接入官方 Usage/Cost/Quota API | OpenAI / Anthropic / Gemini 官方用量读取，与网关观测分列对账 | M2，collector 模块 |
| G3 | Keychain / 跨平台 Vault | CLIProxyAPI 凭据明文文件 | macOS Keychain 优先，跨平台系统密钥库封装 | M2，credential vault（前置项） |
| G4 | 数据来源与可信度标记 | 无来源标记 | 每个数值带 exact / reported / estimated / unavailable 与来源、采集时间 | M2/M3 |
| G5 | 产品裁剪 | 含多租户、远程运维、非必要 Provider | 按本地优先定位精简 | M2 集成时 |
| G6 | 中文产品化 | 英文信息架构 | 中文 UI、统一品牌、首次配置向导 | M2 |

### 5.3 计划安全基线缺口（§10 与 FR-16/FR-17）

| # | 缺口 | 处理方案 |
|---|---|---|
| S1 | FR-16：三个上游默认均监听全网卡 | 交付包默认强制 `127.0.0.1`，配置模板固化 |
| S2 | 凭据明文存储（CLIProxyAPI） | 新 M2 的 G3 Keychain 化前置；在完成前限制 `~/.cli-proxy-api` 目录权限并禁止备份 |
| S3 | Provider Base URL 仅 HTTPS、防 SSRF | 配置层强制 HTTPS，拦截云元数据与本机敏感端口 |
| S4 | 前端 XSS 与插件供应链 | 依赖固定提交 + 锁定依赖 + 上游安全更新跟踪 |
| S5 | 日志/备份泄密 | 保留上游脱敏能力，新增凭据扫描作为 CI 门禁 |

## 6. M0 结论与下一步

1. 三个上游构建、测试、运行全部通过，可作为 V0.1 三层基座。
2. 主要风险：CLIProxyAPI 凭据明文存储、默认监听全网卡 —— 必须在对外发布前处理。
3. 下一步（新 M1）：建立自有集成仓库与可重复构建流程，保持上游可更新（先评估差异再合并）。
4. 新 M2 优先级建议：Keychain/Vault（G3/S2）→ 健康评分（G1）→ 官方账单对账（G2）→ 中文产品化（G6）。
5. 需决策门确认：是否继续 M1；M2 的上述优先级是否认可。
