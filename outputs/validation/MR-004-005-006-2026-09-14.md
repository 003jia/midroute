# MR-004/005/006 验收证据（P0-1 账户与能力管理）

> 日期：2026-09-14
> 范围：MR-004（账户生命周期收口）、MR-005（账户/模型界面）、MR-006（账户能力矩阵运行时）

## 一、实现内容

### MR-004 收口（凭据轮换 + 详情接口）
- `POST /api/v1/accounts/{id}/credential`：新密钥先写入 Vault 取得新 SecretRef → 用新凭据解析目标并 `ValidateCredential` → 成功才 `SetAccountCredentialRef` 原子切换 → 失败删除新引用、旧凭据原样保留。
- `GET /api/v1/accounts/{id}`、`GET /api/v1/providers/{id}` 详情接口。
- 新增 repository `SetAccountCredentialRef`、`SetAccountName`（已存在于此前实现）、审计记录轮换成败。
- API 响应只回 `secret_fingerprint`，不返回完整密钥；重复删除返回 404。

### MR-006 账户能力矩阵
- migration v5：`account_capabilities`（account_id, capability, status, reason, connector_version, checked_at，PK 双列）。
- domain：`CapabilityStatus` 扩展为六态（supported/unsupported/permission_required/reauth_required/error/unknown）；`CapabilityName` 八项。
- `internal/accounts.CapabilityChecker.Check`：对每个能力**单独**判定：
  - verifyCredential / discoverModels：凭据可解析才在线验证；否则 error。
  - forward：仅监测账户 → unsupported；认证过期/需重授权 → reauth_required。
  - oauth：平台已登记 OAuth 且账户为 OAuth 才 supported。
  - subscription / quota：按平台与认证方式如实标注（API Key 的 OpenAI → unsupported；codex → unknown“被动响应头待验收”；gemini/anthropic → permission_required）。
  - refresh：仅 OAuth 账户 supported。
  - probeHealth：凭据可用时 supported。
- `GET /api/v1/accounts/{id}/capabilities` 执行检查并持久化返回。

### MR-005 账户/模型界面
- `lib/api.ts` 类型化 API 客户端（密钥只在请求体内）。
- `pages/Accounts.tsx`：列表（状态筛选、模式/认证/指纹展示）、添加向导（平台→名称→模式→密钥）、验证/发现模型/能力矩阵弹窗、编辑（改名+换密钥）、禁用/重新启用/删除、monitor_only 徽标、reauth_required 徽标、空态/错误/加载。
- `pages/Models.tsx`：模型列表、按平台筛选、刷新、由哪个账户发现。
- `App.tsx` 改为 React Router 多页面。
