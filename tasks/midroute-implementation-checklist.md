## 3. 具体实现方法

### 3.1 模块职责与接入边界

- 后端保持 `apps/server`；前端保持 `apps/web`。后端一次启动同时服务静态资源、管理 API 和推理 API。
- `domain` 定义业务类型；`repository` 处理持久化；新增 `accounts`、`quota`、`access`、`scheduler`、`audit`、`notifications` 服务；`api` 只做输入输出、认证授权和调用编排。
- 复用现有 `connectors`，拆分 `ModelConnector`、`SubscriptionReader`、`OAuthConnector`、`HealthProber` 小接口。按能力调用，不要求仅监测账户实现请求转发。
- Provider 能力声明与凭据实测结果分开保存。平台支持某能力，不代表当前 Key 权限足够；能力结果包含 `supported/unsupported/unknown`、原因、连接器版本、测试时间。
- `credentials` 在执行边界解析 SecretRef；HTTP 客户端仅短时持有凭据，不把 Vault 访问、原项目配置或第三方数据库扩散到领域层。
- 新增 `protocols`：分别解析 Chat Completions、Responses、Anthropic Messages。相同协议优先保真转发；跨协议通过结构化内容块/工具事件转换，不把所有内容压成纯字符串。
- Codex OAuth、API Key 推理和官方账单权限分别建模；“可以登录”“可以调用”“可以查额度”必须分别验证。
- OneAPI/CLIProxyAPI/CPA 工作副本只作参考与代码来源；新功能不能通过启动原服务、访问原管理端口来实现。

### 3.2 数据结构与统计口径

| 对象/表（现有表增量迁移） | 关键字段与实现规则 |
|---|---|
| `accounts` | `mode=monitor_only/relay_and_monitor`；`auth_type=api_key/oauth/manual`；`billing_mode=subscription/metered/unknown`；禁用状态与认证状态分列；凭据仍为 SecretRef |
| `account_capabilities` | 账户、能力、支持状态、缺失权限、检查时间、Connector 版本；不保存原始认证响应 |
| `subscriptions` | 套餐名称、到期/续费时间、读取方式、来源、可信度；不明字段为 `null`；手工值不能覆盖官方原始值 |
| `quota_pools` / `quota_pool_members` | 平台、外部组织/账号标识、共享范围、成员账户与模型范围；只有官方证据或明确手工绑定才合并，不能仅凭同名模型判断共享 |
| `quota_snapshots` | `pool_id`、窗口类型、窗口起止、`reset_at`、`unit`、limit/used/remaining、来源、新鲜度、采集时间、连接器版本 |
| `usage_events` / `request_attempts` | 逻辑请求 ID、尝试 ID、Provider/Account/模型快照、协议、访问令牌 ID、状态、Token 明细、计量完整度、价格版本；不存正文 |
| `price_versions` | Provider+模型+生效区间+币种+计价单位；区分普通输入、缓存读取/写入、输出等；费用以定点数或十进制定精度表示 |
| `projects` / `access_tokens` | 名称、令牌摘要、末尾识别码、模型白名单、到期/撤销、预算、并发；原始令牌只在创建时展示一次 |
| `budget_reservations` | 项目/令牌、请求 ID、预算周期、预留额、结算额、状态；并发占用原子化，崩溃后可恢复 |
| `health_samples` / `health_states` | 账户/模型/网络路径、TTFT/延迟/错误、采样类型、统计窗口、置信度、状态机版本；不把单账号限额算作平台拥堵 |
| `routing_policies` / `route_sessions` | 模型候选、优先级、权重、策略类型、允许付费回退、会话保持时限、跨平台允许范围；协议状态句柄按原账户绑定 |
| `refresh_jobs` / `notification_events` | 去重键、状态、开始/完成/下次执行、重试计数、失效原因、提醒冷却与恢复事件 |
| `audit_events` | 操作者、动作、目标、变更摘要、request_id、时间；记录管理操作及选路原因，不存 Secret 或原始请求 |

统一数据语义：

1. `source=official/reported/observed/estimated/manual`；分别表示官方支持的读取方式、上游报告但非已确认官方能力、本地观测、估算、手工输入。附 `source_ref` 描述依据。
2. `confidence=exact/reported/estimated/unavailable` 描述精度；`availability=available/unsupported/permission_required/reauth_required/error/unknown` 描述能否读取；`freshness=fresh/stale/unknown` 描述时效。三者不能混成一个枚举。
3. 所有未知数字用 `null`，已知零用 `0`。失效刷新保留上次成功值但标记过期；`collected_at`、`last_success_at`、`expires_at` 分开。
4. 窗口采用 `rolling/fixed/calendar/billing/unknown`，保存时区及真实边界；并存 5 小时与一周限制，不相加。缺上游重置时间时不得用“当前时间加 5 小时”伪造。
5. 单位采用 `tokens/requests/percent/currency` 并记录币种；百分比没有已知分母时不换算成 Token。仅在单位、范围和来源一致且规则确定时推导 remaining。
6. 共享池只展示一次总额，成员账户引用它。官方已用量可能包含绕过 Midroute 的请求，本地已用量只统计本平台流量，两者分列。
7. Token 统计保留供应商含义：cache、reasoning 可能是 input/output 子集，不再次叠加总量；缓存读写不同价分别保存，缺值保持未知。
8. 一个逻辑请求可有多次上游尝试。重试可能产生多份真实消耗，逐次记录；重复写入靠 `(request_id, attempt_id)` 去重，不把多次消耗误删成一次。

以下为目标接口，不表示当前均已存在。管理响应统一错误结构 `error.code/message/request_id/retryable`；异步操作返回 `202 + job_id`，列表使用游标分页。协议推理接口遵循各自错误格式，内部映射到同一错误分类。

### 3.4 关键运行流程

- 添加账户：选择平台和模式 → 填凭据或授权 → Vault 保存 → 账户元数据入库 → 返回能力检查任务 → 分别发现模型、读取套餐/额度 → 显示支持范围。
- 刷新：按账户和能力去重 → 读取最新有效 SecretRef → 独立超时调用 → 规范化数据 → 快照事务落库 → 更新成功时间 → 发出变更事件。某项失败不能把其他成功数据清零。
- 请求：校验项目令牌 → 验证协议/模型能力 → 过滤禁用/监测专用/额度用尽/熔断候选 → 执行策略 → 预留预算 → 建立请求与尝试记录 → 转发 → 有界结算落库 → 更新健康与审计。
- 回退：先判断是否能安全重试，再判断模型能力、允许平台及付费回退开关；同一会话优先原账户。流式首个响应块已发送后不整请求重放；已执行与否不明的超时不得盲目重试。
- 恢复：读取未完成任务/预算预留 → 将中断请求标为结果未知 → 有依据才补账 → OAuth 刷新按凭据版本更新 → 不自动重放可能已计费的业务请求。

## 5. 编写与协作规范

### 5.1 代码结构及语言规则

- 采用 Go、TypeScript、React、HTML/ESNext 规范中适用规则；遵循当前 Go 模块与 React 19/TS/ESM 技术路线。语言特定规则优先；旧 AMD、`.es` 扩展名及类组件专属生命周期/defaultProps 约束不引入现代 TS 函数组件。规则适用性在 lint 配置和 `docs/contracts/` 中说明，不机械移植旧技术写法。
- Go 代码 `gofmt`，tab 缩进，建议单行不超过 160 字符；文件名小写下划线，包名全小写无下划线；导出类型/公共 API 注释以其名称开头，包注释以 `Package` 开头。
- Go 名称用驼峰，错误变量 `err/Err` 前缀，receiver 简短一致不用 `self/this`；构造 struct 使用字段名；import 按标准库、第三方、自有包分组；禁止点导入，匿名导入说明原因。
- `context.Context` 为首参数，error 为末返回值；错误保留 `%w`，使用 `errors.Is/As` 分类。不得按 `err.Error()` 的英文片段判断限额或重试；Go 内部 error 小写开头且无句末标点，用户中文文案在 API/UI 层映射。
- 每个 error 都处理，禁止静默 `_ = RecordUsage...`、忽略数据库写失败或吞掉解码错误；defer 中关键清理失败也应记录。不得在循环内累积 defer；持有锁的 struct 用指针 receiver；goroutine 必须有退出条件。
- TS/TSX 使用 strict 类型、ESM、const/let、严格相等；接口/类型 PascalCase，无 `I` 前缀；组件 PascalCase 且与文件名相同；简单数组用 `T[]`，复杂类型用 `Array<T>`。
- 外部 JSON 在 API 边界校验，未知值先用 `unknown`，不以 `any`、非空断言或空 catch 绕过检查。状态枚举优先字面量联合，避免与现有 isolatedModules 冲突。
- 新增 JS/TS/HTML 统一 4 空格、语句分号、JS 单引号/JSX 属性双引号、120 字符行宽、文件末尾换行；MR-001 配置格式工具，存量 2 空格/无分号代码的机械调整独立提交，避免混入业务差异。
- 文件与公共函数说明用途，复杂计算说明单位/包含关系/失败边界；注释解释意图，不用“已安全”“已完成”替代证据；TODO 必须带 MR 编号。
- React 使用函数组件和 hooks，组件不内嵌声明；不修改 props/state，依赖旧 state 的更新使用函数式 setter；列表 key 用稳定 ID；hook 不在条件中调用，依赖项完整，副作用释放连接/请求/定时器。
- HTML 使用语义标签，输入关联 label、button 指定 type；图标按钮有可访问名称；焦点可见，键盘可操作；金额/时间/百分比共用格式化函数，用户可见文案统一中文。

### 5.2 API、数据库与并发规则

- 管理 API 输入 DTO、领域对象和第三方响应分开；统一校验、大小限制、分页上限、错误码与 request_id。关键失败不可只返回“500，请重试”。
- 数据库参数化查询，新增字段通过 migration；不修改已发布迁移、不直接手改用户库、不把纯内存测试当成迁移验证。
- 内部 ID 不等于上游模型名；持久记录同时保留内部引用与当时上游标识。历史归属不依赖仍存活的账户行。
- 时间存 UTC，界面按用户时区展示；计量显式带单位，金额禁止 float64 累加；未知值和真实零必须在数据库/API/UI 全链路区分。
- DB 写事务保持短小，不在事务内执行上游网络请求。OAuth 刷新、预算预留、任务去重和事件写入明确并发控制与幂等键。
- 流式处理采用有界缓冲，不把长回答完整积攒进内存；客户端取消传播上游；计量收尾使用独立超时但不无界阻塞退出。
- 外部调用有超时、大小/连接上限和有限重试，重试依据结构化分类和已发送状态；遵守 Retry-After，不把所有 timeout/5xx 都视为安全重放。
- Base URL 验证 scheme/host/端口和重定向目标；不接受用户信息段或任意 scheme。私网/本地自建端点通过明确配置许可，凭据不跨主机重定向透传。

### 5.3 凭据与日志规则

- 上游 API Key/OAuth Token 放 Vault；业务表只放 SecretRef。高熵项目令牌只存不可逆摘要；会话 cookie 使用适合部署模式的安全属性。
- 禁止把 Secret 放 URL、异常原文、访问日志、截图、fixture、导出、Git、命令行参数或前端持久存储；调试样例用明显假值。
- 统一脱敏覆盖请求头、错误链、上游响应摘要和管理审计；不能只扫描正常日志。上传日志/诊断包前再检查内容。
- 默认只保存请求元数据；Prompt、代码、工具参数、模型回答均不落库。故障样例先用人工构造或彻底脱敏数据。
- 本地免登录只属于受限管理模式；反向代理、远程监听和推理项目令牌分别验收，不能由客户端声称自己是 loopback。
- Keychain 不可用时，持久账户创建/刷新应明确失败；内存 Vault 只允许显式测试/开发模式。

### 5.4 开源代码融合规则

1. 先核实原仓库、完整提交 SHA、许可证及依赖，再读对应最小模块；不得按项目整体许可推断所有嵌套文件许可。
2. 台账记录源路径 → 目标路径 → 修改说明 → 适用版本 → 验收 fixture；区分直接复制、改写与仅参考行为。
3. 直接移植保留版权与完整许可，原项目全局变量、数据库、端口、登录和服务启动逻辑替换成 Midroute 接口。
4. 每个 Connector 独立注册能力和版本，升级上游先对比固定提交并跑契约测试，不直接覆盖整个目录。
5. 不支持的协议/字段/额度方式写明边界；不能为了满足测试制造上游从未保证的行为。
6. README/台账中记录未解决的不兼容；发布前复核实际依赖许可。自动扫描负责可检测规则，人工审查负责来源真实性。

### 5.5 每个任务的执行规范

1. 读取对应 MR、依赖和代码，确认依赖已验收或只使用明确的 mock 合约；有未提交改动先区分来源。

| 改动类型 | 必做验证 | 证据要点 |
|---|---|---|
| Go 业务/API | 单测、go vet、相关 SQLite/HTTP 集成 | 真实失败分支、状态变化、退出码 |
| 额度/费用 | 多窗口/单位/共享池/零与未知/精度/包含关系 | 固定时间和输入下的预期数值 |

| 协议/Connector | 脱敏 fixture 合约及声明支持的真实平台/工具验收 | Provider/客户端版本、原生与转换路径、限制 |
| UI | type-check/lint/build；真实桌面及移动浏览器关键操作 | 成功、空、加载、错误、权限与过期状态截图 |
| migration/备份/导入 | 新目录执行升级、失败回滚、备份恢复、dry-run/幂等 | 数据与 schema 校验、原库未修改 |
| 发布 | 全量 test/build、修正后的 smoke、secret/license/依赖检查 | 安装包、锁定版本、扫描日期及剩余风险 |

MR-030 负责实现新增来源/依赖门禁，MR-028 负责迁移恢复检查；未创建的脚本不能在 README 写成“已通过”。凭据和真实计费测试不进入默认离线 test 路径，需要明确账户与小额测试范围。
