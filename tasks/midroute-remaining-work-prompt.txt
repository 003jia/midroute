以下内容已经存在，不要重复搭建，也不要把它们重新改造成 OneAPI、CLIProxyAPI 或 CPA-Manager-Plus 的运行服务：

1. 单个 Go 后端入口：apps/server/cmd/server。
2. React + TypeScript 前端骨架：apps/web。
3. SQLite 版本化 migration、Keychain/Vault、SecretRef 和本地安全边界。
4. OpenAI-compatible、Anthropic、Gemini Connector 的基础验证、模型发现和转发能力。
5. /v1/chat/completions、/v1/models、/v1/responses 基础路径。
6. Responses 协议原样透传、previous_response_id 账户绑定。
7. OAuth 管理 API 的 start、complete、flows、revoke 基础接线。
8. Codex 额度响应头解析器和 Provider 能力矩阵初版。

10. M0/M1 工程基线、安全边界、构建、测试和基础冒烟已经通过。

【P0-1：完成账户和能力管理】

对应任务：MR-004、MR-005、MR-006。

实现内容：

1. 补齐 Provider/Account 的详情、编辑、禁用、重新启用和删除接口。
2. 支持 monitor_only 与 relay_and_monitor 两种账户模式。
3. 增加账户能力矩阵：模型发现、请求转发、OAuth、套餐读取、额度读取、刷新、健康探测。
4. 每个能力必须返回 supported、unsupported、permission_required、reauth_required 或 unknown，以及原因、Connector 版本和检查时间。
5. 前端完成账户列表、添加向导、编辑、禁用、删除、验证和模型发现页面。
6. 仅监测账户绝不能进入路由候选。

注意事项：

- 更换凭据时先保存新 SecretRef，验证成功后再原子切换；验证失败必须保留旧凭据。
- API、日志、错误、截图和浏览器持久存储中不得出现完整密钥。
- 删除账户前检查路由策略、历史用量和额度快照引用；有历史数据时保留历史归属。
- 账户“能登录”“能转发”“能读套餐”“能读额度”必须分别判断，不能用一次 API 成功代替全部能力。
- 不要因为某平台存在网页显示额度，就假定存在可合法调用的额度 API。

【P0-2：完成首个真实 Coding Plan 额度闭环】

对应任务：MR-007、MR-008、MR-009、MR-010、MR-011。

实现内容：

1. 完成已验证平台的 OAuth 授权码/PKCE 或平台实际要求的授权流程。
2. 完成 Token 刷新、刷新失败保留旧凭据、明确 reauth_required 和本地撤销。
3. 读取套餐、订阅状态、5 小时窗口、一周窗口及重置时间；无法读取时返回明确 unavailable 或 permission_required。
4. 建立共享额度池，多个 Key 共用同一额度时只统计一次。
5. 增加 quota_snapshots 历史查询、手工补充和来源/可信度/新鲜度字段。
6. 增加后台刷新任务：去重、超时、并发上限、Retry-After、退避、失败恢复和任务状态查询。

注意事项：

- 5 小时、一周、自然日和账单周期是不同窗口，不能互相推导。
- 没有官方 reset_at 时，不得使用“当前时间 + 5 小时”伪造重置时间。

- 缺少真实账户或权限时，只能完成 fixture、mock 和能力声明，不能勾选真实验收项。
- Token、refresh_token、OAuth code、state、PKCE verifier 不得进入 URL 日志、普通数据库字段或 Git。

三、统一开发规范

1. 先读对应 MR 和问题编号，再改代码；只修改任务范围内的文件。
2. 跨模块字段先更新 docs/contracts，再更新 migration、domain、repository、service、API 和页面。
3. Go 必须 gofmt、go vet；错误用 errors.Is/As 分类，context.Context 放首参数，error 放最后返回值。
4. TypeScript 使用 strict、ESM、const/let、严格相等；不使用 any、非空断言和空 catch 绕过类型检查。
5. React 使用函数组件和 hooks；完整处理加载、空数据、权限失败、过期、错误和重试状态。
6. 时间统一存 UTC，前端按用户时区显示；所有数字都带单位和来源。
7. Prompt、回答、代码、工具参数、完整请求体不得写入数据库、日志、审计、导出或截图。
8. 外部 HTTP 请求必须有超时、取消、响应大小限制、重定向边界和有限重试。
9. 不得使用原项目的全局配置、数据库、端口、登录体系或常驻服务作为运行依赖。
10. 不得用注释、mock 测试或文件存在来代替真实验收证据。
