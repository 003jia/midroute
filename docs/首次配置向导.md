# 中间路由平台 · 首次配置向导（V0.1 本地模式）

> 目标：10 分钟内完成「添加凭据 → 验证 → 本地网关可用」。所有服务默认只监听 `127.0.0.1`。

## 0. 前置条件

- macOS（凭据走系统 Keychain）、Go 1.26+、Node 20+。
- 已克隆并固定三套上游（见 `PINNED_COMMITS`）。

## 1. 构建与冒烟

```bash
./build/build.sh        # 一键构建
./build/smoke-test.sh   # 三服务冒烟（可选，验证环境）
```

## 2. 凭据入库（Keychain，不落明文）

以 OpenAI 为例，通过 stdin 写入系统 Keychain：

```bash
printf '%s\n' 'sk-你的真实Key' | ./dist/bin/vaultctl store openai conn-default
# => stored ref: service=midroute-openai account=conn-default fingerprint=xxxx
```

- `vaultctl get` 只返回引用与指纹，不打印原始密钥。
- 注意：`~/.cli-proxy-api/` 内的 OAuth 登录凭据目前仍为上游明文文件，M2 的 Keychain 接线完成前，请勿将该目录纳入备份/同步。

## 3. 启动本地服务

```bash
./build/run-local.sh
```

- 网关: `http://127.0.0.1:8317`（`/v1/chat/completions`、`/v1/responses`、`/v1/models`）
- 管理台: `http://127.0.0.1:18317/management.html`
- OneAPI: `http://127.0.0.1:13000`（渠道、令牌、统一中继）
- 本地运行会自动启用仅限 `127.0.0.1` / `::1` 的管理台免密模式，并自动把 Manager Server 接到本地网关；首次进入时不需要管理员密钥或 CPA Management Key。
- 网关访问 Key 会打印在启动输出中，请妥善保管。远程/非本地部署不要开启 `CPA_MANAGER_LOCAL_MODE`。

`run-local.sh` 会把本地网关自动注册为 OneAPI 的 OpenAI-compatible 渠道。只有在网关已经返回模型时才会创建/更新该渠道；新增 Provider 或模型后可执行：

```bash
./build/oneapi-sync.sh
```

OneAPI 的数据保存在 `data/oneapi/`，日志保存在 `data/oneapi/logs/`。本地启动默认使用近似 token 统计并跳过远程 tiktoken 文件初始化，保证离线环境可启动；需要精确 token 统计时可在有网络环境下按上游方式运行。OneAPI 首次登录仍遵循上游账户初始化流程，请登录后立即修改默认凭据。

## 4. 把工具指向本地网关

业务工具（IDE / CLI）只需配置一个 Base URL 和一个访问 Token：

```text
Base URL: http://127.0.0.1:8317
API Key:  （启动时打印的网关访问 Key）
```

## 5. 查看官方用量/费用（可选，需组织级管理凭据）

```bash
./dist/bin/billingcheck -provider openai -key 'sk-admin-...' -window-day 7
./dist/bin/billingcheck -provider anthropic -key 'sk-ant-admin...' -window-day 7
./dist/bin/billingcheck -provider gemini            # 无 GCP 凭据时明确显示不支持
```

## 6. 健康评分演示

```bash
cat samples.json | ./dist/bin/healthcheck
```

## 7. 提交前安全门禁

```bash
./build/ci/secret-scan.sh   # 扫描仓库内疑似密钥，出现即失败
```

## 故障排查

- 端口占用：`lsof -iTCP:8317 -sTCP:LISTEN`；用 `MIDROUTE_GW_PORT` / `MIDROUTE_MGR_PORT` 改端口。
- 凭据校验失败：确认 Key 前缀是否具备组织级权限；`billingcheck` 会给出 `unavailable` + 原因，不会伪装成 0。
- 升级上游：先 `./build/sync-upstream.sh` 看差异，评审后 `./build/sync-upstream.sh apply`，再重新构建与冒烟。
